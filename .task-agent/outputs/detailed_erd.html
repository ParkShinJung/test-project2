📊 사용자와 게시글 인터페이스 구조

User-Post 관계도 및 데이터 모델 정의

1. 엔티티 관계도 (ERD)

2. 관계 설명

🔗 User ↔ Post 관계

관계 유형: One-to-Many (1:N)
설명: 한 명의 사용자(User)는 여러 개의 게시글(Post)을 작성할 수 있습니다.
외래키: Post.authorId → User.id
카디널리티: User (1) : Post (0..*)
3. USER 엔티티 상세

📋 필드 정의

id (PK): string - 사용자 고유 식별자 (UUID 또는 자동 생성)
name: string - 사용자 이름 (필수)
email: string - 사용자 이메일 (필수, 유니크)
phone: string - 사용자 전화번호 (선택)
address: string - 사용자 주소 (선택)
isActive: boolean - 계정 활성화 여부 (기본값: true)
createdAt: Date - 계정 생성 날짜 (자동)
updatedAt: Date - 계정 수정 날짜 (자동)
4. POST 엔티티 상세

📋 필드 정의

id (PK): string - 게시글 고유 식별자 (UUID 또는 자동 생성)
title: string - 게시글 제목 (필수)
content: string - 게시글 내용 (필수)
authorId (FK): string - 작성자 ID (필수, User.id 참조)
author: IUser - 작성자 정보 (선택, 관계 로딩)
category: string - 게시글 카테고리 (선택, 예: notice, general, question, review, free)
tags: string[] - 태그 목록 (선택, 배열)
viewCount: number - 조회수 (기본값: 0)
likeCount: number - 좋아요 수 (기본값: 0)
commentCount: number - 댓글 수 (기본값: 0)
isPublished: boolean - 공개 여부 (기본값: false)
isPinned: boolean - 고정 여부 (기본값: false)
createdAt: Date - 게시글 생성 날짜 (자동)
updatedAt: Date - 게시글 수정 날짜 (자동)
deletedAt: Date - 게시글 삭제 날짜 (선택, 소프트 삭제)
5. 인터페이스 계층 구조

🏗️ 아키텍처 레이어

Controller Layer: IUserController, IPostController - HTTP 요청 처리
Service Layer: IUserService, IPostService - 비즈니스 로직 처리
Repository Layer: IUserRepository, IPostRepository - 데이터베이스 접근
Interface Layer: IUser, IPost, ICreateUserRequest, ICreatePostRequest 등 - 데이터 계약
Type Layer: UserRole, PostCategory, UserFilterOptions, PostFilterOptions 등 - 타입 정의
6. 주요 특징

✨ 설계 특징

관계 로딩: Post 조회 시 author 필드를 통해 User 정보를 선택적으로 로드 가능
소프트 삭제: Post의 deletedAt 필드로 논리적 삭제 구현
메타데이터: viewCount, likeCount, commentCount로 게시글 인기도 추적
상태 관리: isPublished, isPinned로 게시글 상태 제어
필터링: PostFilterOptions, UserFilterOptions로 유연한 검색 지원
페이지네이션: PostPaginationOptions, UserPaginationOptions로 대량 데이터 처리
